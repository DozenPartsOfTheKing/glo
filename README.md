# Glasspad

Прозрачный блокнот-оверлей для Windows: окно поверх всех окон, прозрачность подложки
0–100% при всегда непрозрачных буквах, плашка-маркер под текстом, белые или чёрные
буквы, шрифт 8–72.

Инструкция для пользователя — в `ИНСТРУКЦИЯ.txt` (обычный текст, можно просто переслать).
Здесь — техническая часть.

## Что где лежит

| | |
|---|---|
| `Glasspad.exe` | сборка для 64-битной Windows, зависимостей нет |
| `src-go/` | исходники: Go + чистый Win32 через `syscall`, без сторонних пакетов |
| `src-go/build.sh` | пересборка exe |
| `glasspad.py` | та же программа на Python/tkinter |
| `Glasspad (Python).bat` | запуск питоновской версии без окна консоли |

Обе версии читают и пишут одни и те же файлы в `%AppData%\Glasspad\`:
`note.txt` (автосохранение раз в 5 секунд и при выходе) и `settings.json`.

## Пересборка

```
sh src-go/build.sh
```

Кросс-компиляция работает с любой ОС, где есть Go, — Windows для сборки не нужна:

```
GOOS=windows GOARCH=amd64 go build -ldflags "-H=windowsgui -s -w" -o Glasspad.exe ./src-go
```

Только amd64: раскладка `OPENFILENAMEW` в `win32.go` рассчитана на 64-битное
выравнивание, под GOARCH=386 файловые диалоги сломаются.

## Как устроена прозрачность

`SetLayeredWindowAttributes` умеет либо равномерную альфу на всё окно, либо ключевой
цвет — то есть «полупрозрачный фон при непрозрачных буквах» одним окном не собрать:
`LWA_ALPHA` гасит и текст тоже. Попиксельная альфа (`UpdateLayeredWindow`) потребовала
бы рисовать текст самому, вместе с кареткой и выделением. Поэтому окон два:

- **подложка** (`GlasspadBackdropWnd`) — сплошная заливка, `LWA_ALPHA` = ползунок.
  `WS_EX_NOACTIVATE`, фокус не забирает;
- **основное окно** — `LWA_COLORKEY` с цветом `#FF00FE` и **без** `LWA_ALPHA`. Фон
  проваливается насквозь, всё нарисованное поверх непрозрачно при любом ползунке.

`syncBackdrop` по `WM_WINDOWPOSCHANGED` держит подложку ровно под основным окном:
вставка через `SetWindowPos(hBack, hwnd, …)` заодно синхронизирует признак «поверх
всех» в обе стороны — размещение за не-topmost окном снимает topmost автоматически.

Поле ввода — обычный `EDIT`. В `WM_CTLCOLOREDIT` ему отдаётся кисть ключевого цвета,
`SetBkColor` (ключевой цвет, а в режиме маркера — цвет плашки) и **всегда**
непрозрачный `SetBkMode`: контрол сам рисует плашку под глифами. Прозрачный
`SetBkMode` здесь ставить нельзя, хотя вне маркера и кажется, что фон рисовать
незачем: `EDIT` перерисовывает изменённую строку одним `TextOut` и рассчитывает,
что тот сам затрёт старые пиксели фоновым цветом. Без затирания стёртая буква
остаётся на экране, а новая ложится поверх неё. Цвет подложки берётся из палитры
(тот же, что у плашки).

`InvalidateRect` везде вызывается с `bErase = TRUE` — по той же причине: смена
шрифта, размера или палитры иначе оставляет под новым текстом старый.

Пиксели ключевого цвета у слоёного окна не только невидимы, но и не ловят мышь.
Поэтому клики по пустому месту заметки принимает подложка (`WM_LBUTTONDOWN` →
`SetForegroundWindow` + `SetFocus` на `EDIT`), а `WS_EX_TRANSPARENT` вешается на неё
только когда прозрачность выкручена в 0 или включён сквозной клик.

Сглаживание шрифта переключается автоматически (`wantFontQuality`): без плашки и при
подложке тусклее 25% буквы ложатся почти на голый ключевой цвет, сглаженные края
смешиваются с ним и дают розовую кайму — там ставится `NONANTIALIASED_QUALITY`.

## Заметки по коду

- `runtime.LockOSThread()` в `init()` — обязателен. Очередь сообщений в Windows
  принадлежит потоку, создавшему окно, а главная горутина Go после блокирующего
  вызова спокойно переезжает на другой поток. Тогда окно создано на одном потоке,
  `GetMessage` крутится на другом, и приложение виснет с «не отвечает» — при том,
  что первая отрисовка успевает пройти (её делает `UpdateWindow` синхронно).
- Рамки у окна нет (`WS_POPUP` + `WM_NCCALCSIZE` → клиентская область на всё окно),
  таскание и растягивание сделаны через свой `WM_NCHITTEST`: пустое место панели —
  `HTCAPTION`, края — `HTLEFT`/`HTBOTTOMRIGHT` и т.д. `WS_THICKFRAME` оставлен,
  иначе система не начнёт ресайз.
- Поле ввода отступает от краёв на 6 px, чтобы полоски для растягивания
  оставались за родительским окном, а не за дочерним контролом.
- Оконная процедура принимает все четыре параметра как `uintptr`:
  `syscall.NewCallback` не умеет аргументы меньше машинного слова.
- Везде, где Go-указатель уходит в Win32 как `uintptr`, после вызова стоит
  `runtime.KeepAlive` — иначе сборщик вправе освободить буфер во время вызова.
- Единственное предупреждение `go vet` — `unsafe.Pointer(lp)` в `WM_GETMINMAXINFO`.
  Там система сама передаёт указатель числом, так и должно быть.

## Журнал

Сборка пишет `%AppData%\Glasspad\debug.log`, перезаписывая его на каждом запуске.
Формат: время от старта, вехи запуска, пары `IN #N 0x****` / `OUT #N 0x****` вокруг
каждого обработанного сообщения (шумные вроде `WM_MOUSEMOVE` и `WM_NCHITTEST`
отфильтрованы) и раз в секунду строка «пульс».

Как читать при зависании:

- есть `IN #N`, нет `OUT #N` → встали внутри обработчика этого сообщения;
- идут «пульс», но окно не реагирует → цикл жив, дело в отрисовке или вводе;
- журнал обрывается на вехе запуска → не дошли до цикла сообщений.

Запись идёт обычным `WriteFile` без `Sync`: данные уходят в кеш ОС и переживают
снятие задачи, так что последняя строка — это честное место остановки.

## Статус проверки

Первый запуск на Windows: панель отрисовалась корректно, дальше окно повисло —
не хватало `runtime.LockOSThread()`. Исправлено; после этого добавлена схема с
двумя окнами (непрозрачные буквы), на живой машине она ещё не проверялась.

Второе «зависает» пришло уже с новой сборкой, и, судя по всему, зависанием не
было: окно было `WS_EX_TOOLWINDOW` — ни кнопки в панели задач, ни Alt+Tab, ни
системного меню, а инструкция до пользователя не дошла. Закрыть его он мог
только через диспетчер задач, который и показывает диалог «не отвечает».
Отсюда `WS_EX_APPWINDOW`, значок в трее с пунктом «Выход» и приветственный
текст в самой заметке. Журнал (см. выше) добавлен, чтобы проверить это, а не
предполагать: если зависание настоящее, последняя строка покажет место.

Что смотреть при следующем запуске:

- ползунок гасит подложку, но не текст — это главное;
- подложка не отстаёт при перетаскивании окна и не вылезает поверх него;
- `Поверх` выключается вместе с подложкой (проверка обеих сторон z-порядка);
- клик по затемнённой подложке ставит фокус в текст;
- каретка видна при подложке около нуля;
- полоски ресайза (6 px по бокам и снизу, 3 px сверху) и раскладка кнопок
  панели — их ширина считается по ширине текста системным шрифтом.

Питоновская версия к этой схеме не приводилась: там прозрачность по-прежнему
общая на всё окно, буквы гаснут вместе с фоном.
